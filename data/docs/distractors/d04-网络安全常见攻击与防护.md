# 网络安全常见攻击与防护

## 概述

Web 应用的主要风险集中在输入处理、身份认证和权限校验三个环节。本文梳理注入类、跨站类、越权类攻击的原理与防护手段，以及防护措施为什么必须放在服务端。

## 注入类攻击

SQL 注入的原理是应用把用户输入直接拼进 SQL 语句，导致输入被数据库当作指令解析。

防护手段按可靠性排序：最可靠的是使用参数化查询，让数据库把输入当数据而非语法；其次是严格的白名单校验；再次是最小权限原则，应用账号不应拥有建表和删库权限。字符串转义和黑名单过滤只能作为补充，因为它们依赖不完整的规则集合，容易被编码变形绕过。

命令注入同理，根源是把外部输入传给 shell，防护核心是避免拼接、避免使用 shell 解释器。

## 跨站类攻击

跨站脚本（XSS）是攻击者把脚本注入到页面，在其他用户的浏览器里执行，从而窃取会话或伪造操作。

按注入位置分为存储型、反射型和 DOM 型。存储型危害最大，因为恶意内容持久化在服务端，所有访问者都会中招。

防护的关键是输出编码：在把数据渲染到 HTML、属性、脚本或 URL 等不同上下文时，使用对应的编码规则。仅做输入过滤不够，因为同一份数据在不同上下文中需要不同的转义方式。

跨站请求伪造（CSRF）则是诱导已登录用户在不知情的情况下发起请求。防护依赖校验来源头、使用一次性令牌、以及把关键 Cookie 设置为不允许跨站携带。

## 越权与认证问题

越权分为水平越权和垂直越权。水平越权是用户访问了同级其他用户的数据，垂直越权是普通用户执行了管理员操作。

根因通常是权限校验只在前端做，或者只校验了资源是否存在而没校验归属。正确做法是在服务端对每个涉及资源的接口显式校验当前身份对该资源的操作权限。

身份认证方面，密码必须加盐哈希存储，会话令牌要有有效期并支持主动失效。

## 要点清单

- 参数化查询是防注入的根本手段，转义和黑名单只是补充
- XSS 防护的关键是输出编码，且要按上下文选择编码方式
- 存储型 XSS 危害最大，恶意内容会持续影响所有访问者
- CSRF 防护依赖来源校验和一次性令牌
- 权限校验必须放在服务端，且要同时校验身份与资源归属
- 最小权限原则能显著降低被攻破后的影响范围
