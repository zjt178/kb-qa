# 数据库 MySQL 索引与事务隔离

## 概述

索引决定查询能不能走快速路径，事务隔离级别决定并发读写时的可见性规则。本文梳理 B+ 树索引原理、最左前缀原则、回表与覆盖索引，以及四种隔离级别对应的并发问题。

## B+ 树为什么适合做索引

B+ 树是多路平衡查找树，非叶子节点只存键值，叶子节点存数据并用链表相连。

只存键值意味着单个节点能容纳更多键，树高更低。磁盘按页读取，树高每降低一层，就少一次随机 IO。叶子节点串成链表则让范围查询可以顺序扫描，不必反复回溯父节点。

这也是为什么哈希索引虽然等值查询是常数级，却无法胜任范围查询和排序——它不保留顺序。

## 最左前缀与索引失效

联合索引按定义顺序逐列排序，因此查询条件必须从最左列开始连续匹配才能利用索引，这叫最左前缀原则。

常见失效场景包括：在索引列上做函数运算或隐式类型转换、以通配符开头的模糊匹配、用不等于条件、以及范围条件之后的列无法继续用于排序。

一个典型例子是字符串列用数字去查。数据库会做类型转换，相当于对列施加了函数，索引直接失效。这类问题往往在数据量小时看不出来，上线后才爆发。

## 回表与覆盖索引

二级索引的叶子节点只存索引列和主键，查其他列需要拿主键回聚簇索引再查一次，这个过程叫回表。

如果查询涉及的列都在索引里，就不需要回表，称为覆盖索引。把高频查询的返回列加入联合索引，虽然增加了索引体积，但能省掉大量随机 IO，通常值得。

## 事务隔离级别

**读未提交**：能看到其他事务未提交的修改，会产生脏读。

**读已提交**：只能看到已提交的数据，避免脏读，但同一事务内两次查询可能结果不同，即不可重复读。

**可重复读**：事务内多次读取结果一致，通过多版本并发控制实现。MySQL 默认级别。仍可能出现幻读，即两次范围查询的行数不同。

**串行化**：事务串行执行，安全但并发能力差。

## 要点清单

- B+ 树叶子节点带链表，兼顾等值与范围查询
- 哈希索引只支持等值查询，不支持范围和排序
- 联合索引遵循最左前缀，条件要连续匹配
- 索引列上做运算或类型转换会导致索引失效
- 覆盖索引避免回表，是高频查询的优化重点
- 隔离级别越高并发问题越少，但吞吐越低
