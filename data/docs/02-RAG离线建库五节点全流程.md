# RAG离线建库五节点全流程
## 环境准备
配置所需要的环境、读取文件的路径、嵌入模型，生成大模型、文本块等等。
## 数据加载与清洗
收集各类结构化或非结构化的数据（pdf、txt、csv、html等）

可以使用langchain来读取文件，转为document对象统一管理
## 文档分块
### 定义
将长文档切分为多个较短的chunk，便于后续的检索和匹配。因为上下文长度有限制，确保嵌入内容尽可能减少噪声，同时保证语义的关联性。
### 分类
- 直接切分：按照固定字节长度进行切分，默认是\n\n只在空行段落之间切分
- 递归切分：按照段落、行、句子、单词等进行递归切分，直到满足固定长度要求
- 语义切分：用嵌入模型计算相邻句子的相似度，在语义突变处断开（主题换了才切，而不是按固定长度切）
## 向量化（Embedding）
将分块得到的文本块转为向量

如何转为向量有两种实现路线：
- 稀疏嵌入：向量的每一维对应词表中的一个词，大多数维度为 0，只有出现的词记录权重。代表：BM25（关键词权重打分）
- 密集嵌入：把 chunk 丢给 embedding 模型，输出一串稠密的浮点数向量（如 bge 系列每一维都有值）
## 向量库存储
### 工作流程
接受写入 -> 索引构建 -> 查询检索(向量数据库+度量标准) -> 检索后处理
### 常见的索引构建方式
- FLAT(扁平索引)：逐一比较数据库中的所有向量
- IVT(倒排文件索引)：将向量数据聚类来减少查询时需要比较的向量数量
- HNSW(图索引)：构建一个图结构，向量作为图节点，相似向量作为边检索沿着图节点进行跳转查询相似向量
- LSH(局部敏感哈希索引)：构造多个哈希表，向量通过哈希函数映射到不同的哈希表中，查询时通过哈希表进行快速查找
- 量化索引：压缩向量数据来减少存储空间和计算量
### 主流向量数据库
- Milvus:生成级分布式向量库
- Qdrant:轻量高性能
- Faiss:严格来说不是数据库，仅仅用于索引计算
- Chroma:RAG小型数据库
- PGVector:直接使用SQL语法来实现复杂查询
- Elasticsearch:传统搜索引擎扩展向量检索
### 合适的度量标准
- 欧几里得距离：连续实数的特征向量，如图像、音频、视频等。值越小，越相似
- 余弦相似度：文本分析，对模长不敏感，值越靠近1，越相似
- 内积：衡量相似度或相关性。值越大，越相似
