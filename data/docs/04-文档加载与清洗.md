# 04 文档加载与清洗

## 概述
加载是离线链路的第一步：把各种格式的原始文件读进来，转成 LangChain 统一的 Document 对象。
Document 由两部分组成：page_content（文本内容）和 metadata（元信息，如文件路径）。

## TextLoader（纯文本 / Markdown）
读取 .txt、.md 等纯文本文件：
```python
from langchain_community.document_loaders import TextLoader
loader = TextLoader("path/to/text.txt", encoding="utf-8")
documents = loader.load()
```
注意显式指定 encoding="utf-8"，否则在 Windows 上可能因默认 GBK 编码读文件而报错。

## PyPDFLoader（PDF 文件）
读取 PDF，每个页面产出为一个 Document：
```python
from langchain_community.document_loaders import PyPDFLoader
loader = PyPDFLoader("path/to/pdf.pdf")
documents = loader.load()
```
PDF 是排版文件不是文本文件，提取出的文本可能带断行、页眉页脚等噪声，需要清洗。

## 元数据来源
Document 的 metadata 不是我们手写的，而是**加载器在创建 Document 时自动挂上的**。
以 TextLoader 为例，它的源码里有一行：
```python
metadata = {"source": str(self.file_path)}
```
也就是说 source 这个键（文件路径）在文档被读进来那一刻就已经存在了。

这个 metadata 会一路穿过切分、向量化、入库、检索，
最后被引用溯源环节取出来展示在答案下方——这就是"答案能标明出处"的原理。

## 按扩展名选择加载器
- .txt / .md → TextLoader
- .pdf → PyPDFLoader
- .docx → Docx2txtLoader
- 网页 → WebBaseLoader
LangChain 社区包提供了几十种加载器，按需选即可。

## 要点清单
- 加载器负责把文件变成 Document（文本 + metadata）
- metadata 由加载器自动写入，不是我们手写
- source 字段是引用溯源的根基
- 文本类文件要显式指定 utf-8 编码
- PDF 提取的文本需要清洗噪声
