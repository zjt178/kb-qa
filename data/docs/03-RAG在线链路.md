# 03 RAG 在线链路

## 概述
在线链路是用户提问时实时走的那条路：检索 → 组装上下文 → 生成 → 返回引用。
与离线建库（提前把文档向量化存好）相对，在线链路的每一步都直接影响回答速度和准确率。

## 完整流程
用户提问进来后，依次经过四步：
1. **检索**：把用户的问题转成向量，去向量库找最相似的若干文档块
2. **组装上下文**：把命中的文档块拼成一段文本，并给每块编号 [1] [2]，同时记录来源
3. **生成**：把「参考内容 + 用户问题」一起交给大模型，让它基于参考内容作答
4. **引用溯源**：把答案用到的文档来源一并返回，用户可核对答案出处

## 各步骤要点

### 检索
注意这里是给**用户的问题**做向量化，不是给文档——文档在离线阶段已经向量化好了。
检索返回的条数由 TOP_K 参数决定，条数太少容易漏，太多会引入噪声、拉高延迟。

### 生成
系统提示词在这里起决定性作用，它会约束模型：
- 只能根据参考内容回答，不许编造
- 必须在句末标注引用编号 [n]
- 找不到相关内容时要明确说"没找到"，而不是硬编一个答案

### 引用溯源
引用是 RAG 相对纯大模型问答的核心优势之一：答案可核查、可信。
它的实现依赖文档的 metadata 一路传递——加载时挂上的 source 字段，
穿过切分、入库、检索，最后在组装上下文时被取出来展示。

## 要点清单
- 在线链路 = 检索 → 组装上下文 → 生成 → 引用溯源
- 检索时被向量化的是用户问题，不是文档
- TOP_K 控制检索条数，影响召回与噪声的平衡
- 系统提示词是防幻觉的第一道闸门
- 引用溯源依赖 metadata 全链路传递
