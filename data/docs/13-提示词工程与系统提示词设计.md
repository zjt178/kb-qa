# 13 提示词工程与系统提示词设计

## 概述

系统提示词（system prompt）是 RAG 系统防幻觉的第一道闸门。很多初学者把提示词理解成"给模型写一个好看的人设"，但在知识库问答场景里，提示词的核心不是人设，而是**规则**——用明确的约束把模型的自由发挥空间压到最小。本文讲清 RAG 提示词的结构、必备规则，以及为什么"必须拒答"这一条最重要。

## 提示词的三分法：人设 + 规则 + 格式

一条合格的 RAG 系统提示词包含三部分，权重依次递增：

1. **人设（你是谁）**——"你是一个严谨的企业知识库助手"。它决定回答的语气和视角，但**不决定回答的对错**。
2. **规则（能做什么、不能做什么）**——这是主体。只准根据参考内容回答、必须标注引用编号、找不到就必须说找不到。
3. **输出格式（怎么答）**——要求标注 `[n]` 引用、控制长度、用中文分点陈述。

初学者最常犯的错误是只写第 1 部分。只写"你是一个专业的助手"，模型会把检索到的内容当成"参考资料"而不是"唯一依据"，一旦参考内容不完整，它就会用自己的知识补全——这正是幻觉的来源。

## RAG 提示词的必备四条规则

这四条在绝大多数知识库问答项目里都是标配：

1. **只用参考内容回答**，禁止使用模型自身的知识补充。这一条把模型从"答题者"降级成"阅读理解者"。
2. **必须标注引用编号**。答案里的每一句关键陈述后面跟 `[1]` `[2]`，指向参考内容的编号。这是引用溯源能落地的前提。
3. **参考内容里没有答案时，必须明确说"没有找到"**，不许编造、不许推测、不许用常识代替。
4. **控制回答长度**（例如 300 字内），避免模型废话连篇把关键信息埋掉。

## 为什么"必须拒答"这条最重要

模型在训练阶段被大量"回答问题"的样本塑造，它的默认倾向是：**无论如何都要给出一个答案**。这是对齐训练的副作用——一个总是拒答的助手显得没用，所以模型被训练得倾向于回答。

在知识库里没有答案的时候，这种倾向就会直接转化为幻觉：模型会基于统计规律"合理推测"出一个看起来很像样的答案。

第 3 条规则是**唯一能压制这种默认倾向的指令**。实测中，把这条规则删掉再去问一个知识库里没有的问题（比如"公司 2030 年在火星的分公司地址"），模型有很大概率开始编造具体的街道和门牌号。这条规则的有无，直接决定系统能不能通过拒答测试。

## 用示例代替纯规则（few-shot）

只写规则，模型有时仍然"理解不到位"。更有效的做法是给一两个范例：

- **正确回答的范例**：问题 + 带 `[n]` 标注的标准答案
- **正确拒答的范例**：问题 + "根据现有资料，知识库中没有找到相关内容"

示例比规则更有效的原因是：规则是抽象的约束，示例是具体的行为模板。模型可以通过模仿示例来对齐输出格式，尤其是在引用标注这种"格式类要求"上，一个示例往往胜过三段规则描述。

## temperature 的配合

提示词之外，还有一个参数直接决定幻觉率：**temperature**。它控制采样的随机性：

- `0 ~ 0.2`：输出高度确定，几乎每次都选概率最高的 token。**知识库问答、信息抽取、代码生成用这个区间**
- `0.7 ~ 1.0`：有一定创造性，适合写作、头脑风暴
- `1.5+`：开始明显失控，语句可能不通、事实开始漂移

知识库问答的目标是"忠实复述参考内容"，不是"创作"，所以温度必须压低。提示词写好但温度调到 1.5，规则照样会被随机性冲垮。

## 反面案例

反面案例一：**只写人设不写规则**。
提示词是"你是一个专业的 AI 助手，请帮我回答问题"。结果：模型把检索内容当参考，一半靠检索一半靠自己的知识，答案无法验证来源。

反面案例二：**规则互相冲突**。
既说"必须给出完整答案"，又说"找不到就说没有"。模型会优先满足前者，于是开始编。

反面案例三：**规则藏在长提示词中间**。
规则越多，位置越重要。关键约束应该放在提示词的开头和结尾——长上下文中间的内容更容易被模型"忽略"。

## 要点清单

- RAG 提示词 = 人设 + 规则 + 输出格式，规则权重最大
- 四条必备规则：只用参考内容、强制引用标注、找不到就拒答、限制长度
- "必须拒答"是防幻觉的关键一条，它压制的是模型的默认答题倾向
- few-shot 示例比纯规则更有效，尤其在格式约束上
- 知识库问答必须配低温，temperature 建议 0 ~ 0.2
- 规则要放在提示词开头和结尾，避免被长上下文淹没
