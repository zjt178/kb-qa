# 05 文本分块策略

## 概述
分块是把长文档切成一个个短块（chunk）的过程，块是后续向量化和检索的最小单位。
块切得好不好，直接决定检索能不能命中——它往往是 RAG 系统里最值得调的一个参数。

## chunk_size
单个文本块的最大字符数。
设置依据是嵌入模型的上下文窗口，以及用户问题的平均长度。

一般情况下：
- 通用场景：300-800
- 短对话场景：200-400
- 长文档、论文：600-1000

切太大，一块里混着多个主题，检索命中后喂给模型的噪声多；
切太小，一个完整语义被打散，检索到也拼不出完整答案。

## chunk_overlap
相邻两块之间重复的字符数，目的是防止语义在边界处被切断。
一般是 chunk_size 的 10%-20%。

重叠太大 → 内容重复、入库成本和检索噪声都上升；
重叠太小 → 句子被硬生生切成两半，语义断裂。

## 中文分块的特殊性
LangChain 的默认分隔符是按英文习惯设计的（\n\n、\n、空格、句点）。
中文没有空格分词，句子以。！？结尾，所以需要把中文标点加进分隔符列表，
否则切分效果会很差——这是中文 RAG 项目里最常见的坑之一。

## 要点清单
- chunk 是向量化和检索的最小单位
- chunk_size 是最大字符数，不是固定长度
- overlap 一般取 chunk_size 的 10%-20%
- 切太大引入噪声，切太小语义断裂
- 中文必须自定义分隔符，默认的分隔符按英文设计
