# 11 混合检索与 RRF 融合

## 概述
混合检索（Hybrid Search）= 同时跑向量检索和 BM25 关键词检索，把两份结果合并成一个排序列表。
两路各有所长（向量管语义、BM25 管字面），但合并有个技术难题：两路的分数没法直接比较。RRF 就是解决这个问题的标准做法。

## 为什么不能加权求和
最直觉的合并方式是"分数加权相加"，比如 0.7 × 向量分 + 0.3 × BM25 分。
行不通，原因有两个：
1. **量纲不同**：余弦相似度在 0 到 1 之间，BM25 分数轻松冲到 0-30。直接相加，BM25 会碾压向量
2. **分布不稳定**：BM25 的分数范围随查询词、语料变化，就算调好权重，换个查询又失效了

## RRF 的做法：只看排名，不看分数
RRF（Reciprocal Rank Fusion，倒数排名融合）完全绕开分数，只使用**排名**。
每个文档的融合得分 = 它在每路结果里的 1/(k + rank) 之和：

    score = Σ 1 / (k + rank)

其中 k 是平滑常数，惯用值 60；rank 是该文档在这一路结果里的名次（第 1 名 rank=1）。

**举例**：某文档在向量检索排第 1、在 BM25 排第 3：
    向量路得分：1/(60+1) = 0.0164
    BM25 路得分：1/(60+3) = 0.0159
    融合得分：0.0323

另一个文档只在向量路排第 1、BM25 没召回它：
    融合得分 = 0.0164

两个名单都靠前的文档，融合分明显高于单路冠军——这正是我们想要的："语义和字面都说好"的文档最该排第一。

## k=60 在平滑什么
如果 k=0，第一名得 1 分、第二名得 0.5 分、第三名 0.33——第一名权重过猛，名次微小波动会导致融合结果剧烈抖动。
k=60 把整个名次的得分曲线压平：第一名 0.0164、第二名 0.0161、第三名 0.0159——差距平缓，排名靠前就是优势，但不至于一票定生死。
k 的取值相当鲁棒，30 到 100 之间效果差别不大，一般不用调。

## 实现要点
1. 两路各召回 N 条，N 要大于最终需要的 K（比如各召回 20 条，融合后取前 5）——给融合留余量
2. 融合按文档 id 去重累加
3. 我们项目里 `retriever.py` 的 `_rrf()` 函数就是这套逻辑，`RRF_K=60` 配置在 .env 里

## 要点清单
- 混合检索 = 向量 + BM25，两路结果融合成一个排序
- 不能加权求和：量纲不同（0-1 vs 0-30）且分布不稳
- RRF 只用排名不用分数，天然免疫量纲问题
- 公式 Σ 1/(k+rank)，k 惯用 60，作用是压平名次差距
- 两路先多召回（各 20），融合后取前 K（如 5）
